# Purpose

This document describes the Entity Relationship Diagram (ERD) for the AI-Native Operations Platform.

The ERD defines:

- Database entities
- Relationships
- Cardinality
- Ownership
- Foreign key references

It serves as the blueprint for database implementation.

---

# Database Overview

The database follows a relational model.

Primary database:

- PostgreSQL (Supabase)

Primary tenant:

- Organization

All financial records belong to an Organization.

# Relationship Details

## User ↔ Organization

Relationship:

Many-to-Many

Implemented Through:

Member

```
User
   ▲
   │
Member
   │
   ▼
Organization
```

One user may join multiple organizations.

One organization contains multiple users.

---

## Organization → Budget

Cardinality

```
Organization (1)
        │
        ▼
Budget (*)
```

One organization may create multiple budgets.

Every budget belongs to exactly one organization.

---

## Organization → Expense

Cardinality

```
Organization (1)
        │
        ▼
Expense (*)
```

Every expense belongs to exactly one organization.

---

## Budget → Expense

Cardinality

```
Budget (1)
      │
      ▼
Expense (*)
```

One budget funds multiple expenses.

Each expense belongs to one budget.

---

## Expense → Receipt

Cardinality

```
Expense (1)
       │
       ▼
Receipt (*)
```

One expense may contain multiple receipts.

Each receipt belongs to exactly one expense.

Reason:

- Installment payments
- Multiple supporting documents
- Better auditability

---

## Expense → Payment

Cardinality

```
Expense (1)
       │
       ▼
Payment (*)
```

Supports:

- Partial payments
- Multiple payment methods
- Installment settlements

---

## User → Notification

Cardinality

```
User (1)
    │
    ▼
Notification (*)
```

Every notification belongs to one user.

---

## Organization → Invitation

Cardinality

```
Organization (1)
       │
       ▼
Invitation (*)
```

Organizations may invite many members.

---

## Organization → Audit Log

Cardinality

```
Organization (1)
       │
       ▼
Audit Log (*)
```

Every important financial action is recorded.

# Design Decisions

- Organization is the tenant boundary.
- Users are global entities.
- Membership is organization-specific.
- Expenses belong to budgets.
- Receipts belong to expenses.
- Payments belong to expenses.
- Multiple receipts per expense are supported.
- Multiple payments per expense are supported.
- Financial history is never deleted.
- Soft deletion is used where applicable.
